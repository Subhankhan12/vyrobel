Vyrobel is a multi-tenant, AI-native **hotel management SaaS platform** (PMS + channel manager + booking engine + guest/staff PWAs + owner portal + AI agents) for operators running a **mix** of hotels, aparthotels, serviced apartments, villas, and multi-unit rentals.

## Non-negotiable conventions (apply to everything)
- **Tenancy:** every business table has `organization_id`; use the `BelongsToOrganization` trait (global scope + auto-fill + a guard that THROWS if a tenant query runs with no organization context, outside an explicit super-admin context). Never query tenant data unscoped.
- **Primary keys:** ULIDs on all tenant tables (`HasUlids`).
- **Money:** integer minor units (`*_minor` bigint) + ISO-4217 `currency`; use the `Money` cast/value object. NEVER use floats for money.
- **Refunds are BOUNDED (invariant #27):** cumulative refunds against a payment may equal but never exceed the original — enforced in `FolioService::refundPayment()` (the single path, so every caller is covered; never re-implement per controller), same-currency, non-positive rejected, and the guard runs **before** the gateway call (ordering is load-bearing — the gateway moves real money before any row is written). **This is NOT implied by append-only (#7): #7 bounds EDITS, #27 bounds the SUM.** Both were green while a €369 payment took three full refunds.
- **Time:** store UTC; compute guest-facing "today"/day logic in the property's `timezone`. Stay dates are `date`, half-open `[check_in, check_out)`.
- **PII:** `guests.email`/`phone` are encrypted casts. GDPR erase = `anonymize()` (strip PII + set `anonymized_at`) — NEVER soft-delete-and-keep PII. **Contact PII renders on the Guests CRM ONLY** (list + profile); front desk / reservations / inbox are name-only, and a test asserts that perimeter from the outside (invariant #28). **An encrypted column is undone the moment its value is copied somewhere plaintext:** never write guest contact values into `audit_events.before/after` or a `domain_events` payload — record WHICH fields changed, never their values (no erase clears those tables). **Every free-text store ABOUT a guest is their PII and MUST be added to `anonymize()` in the same change that creates its writer** (columns → ID documents → inbox message bodies → note bodies).
- **One reservation, many channels:** a single `reservations` table; the `source` column distinguishes direct/OTA/walk-in/corporate/group. NEVER create parallel per-channel tables.
- **Single inventory write path:** ALL inventory-affecting writes go through `AssignmentService`. No other code inserts or mutates `reservation_units` or `availability` directly. On MySQL this service IS the no-double-booking guarantee (transaction + `SELECT … FOR UPDATE` on availability rows + overlap check).
- **Events:** every meaningful state change writes an `audit_events` row (who did what) AND a `domain_events` row (business event outbox). **Events are recorded INSIDE the service — no controller in this repo calls a recorder.**
- **Termination is BOUNDED (invariant #29):** a reservation that is already terminal (`AssignmentService::TERMINAL_STATUSES` = cancelled/no_show/**checked_out**) cannot be terminated again — guarded inside the private `terminate()`, which BOTH `cancelReservation()` and `markNoShow()` funnel through, so one check covers every caller. **A second termination is a REWRITE, not an append** (it destroys `cancelled_at`/`cancellation_reason` + appends a junk row), which is why #7 never caught it — same blind spot as #27. The OTA inbound path NO-OPS on terminal rather than throwing (a retrying webhook must not become a poison message).
- **Authorization: ROUTE, not service (invariant #30) — and this is the deliberate exception to the guards-go-in-the-service rule.** Sensitive writes carry `can:<permission>` route middleware; **`Authorize` runs last**, after #26 and after `SetTenantForWebRequest` sets the spatie team (⚠️ a null team fails **silently to false** — never place a check above it). A permission is a REQUEST fact about an ACTOR; #27/#29 are DATA bounds about a ROW — services are called by jobs/tests with no user, so `can()` there is meaningless. **Never gate a money route without gating the role-granting route (`owners.invite → users.manage`) in the same change** — otherwise an attacker just invites themselves the role. **Gate the CONTROL too** (`@can`), so the UI never invites a 403. **Fix fixtures, never the check**; and cross-org isolation tests must keep a PERMITTED actor or their `assertNotFound()` silently becomes a masked 403.
- **Operator/owner boundary:** `/app` is gated by `EnsureBackOfficeAccess` — a team-scoped **allow-list** (`config('authorization.back_office_roles')`), on the **group** so no route can forget it. **A Membership is NOT operator access** (owners hold one — it's how their org resolves). Owners hold `External Owner` (`owner_portal.view` only) and are refused at both the route and role level. Gate additions go in that config, never ad hoc per route.
- **Reuse, don't duplicate:** polymorphic `media` / `documents` / `notes` / `tags` are shared across modules. Extend existing services; never build a parallel structure for an existing concept. **When a PDF/document mirrors a screen, the shared rule lives in ONE `App\Support\*` helper** (`MoneyFormatter`, `FolioTotals`, `RailLabel`, `OwnerOccupancy`) — two `match`es for one concept WILL drift and make the two surfaces disagree.
- **Livewire — two traps that cost real bugs (both invisible to PHPStan/Pint):** (1) never type-hint a scoped model as a public prop (RMB resolves before the scope middleware → leak); hold a **string** id and `findOrFail` in `render()`. (2) **name that prop `$xxxId`** — a public prop is injected into the view scope, so `public string $unit` SHADOWS a `'unit' => [...]` array from `render()` and `$unit['name']` fatals on a string offset.
- **Blade — a directive whose `@` follows a word character is NOT compiled** (the `\B` rule that lets `foo@bar.com` render literally): `expenses@if ($x)…@endif` ships **raw source to the user** as ordinary text, which `assertSee`/`assertDontSee` sail straight past. Never write `word@directive`. `assertNoRawBlade()` (tests/Support/owner_helpers.php) guards it.
- **Static checks cannot see a rendered page.** `php -l` + PHPStan + Pint + a Blade compile all pass on a page that 500s or leaks raw source. **Run the suite AND open the thing in a browser** before claiming any gate.

## Workflow rules
- **Audit first:** at the start of a build step, inspect the real code and echo the plan before writing anything.
- **Gated phases:** STOP at every ⛔ gate and wait for approval. Never collapse steps.
- **No faked data, ever:** demo seed data must be clearly flagged as demo. If something isn't actually built, or a test isn't actually passing, say so plainly — never stub-and-pretend to look finished.
- **Tests are real gates:** the double-booking concurrency test and the tenant-isolation test MUST actually pass. Report pass/fail honestly, with file citations.
- **Commit per gate:** commit once at each passing gate with a clear message; never batch multiple gates into one commit.
- **Ask before installing** packages beyond those listed above.
