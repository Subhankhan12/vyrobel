## ⚠️⚠️ THE WRONG-FIX MUTATION — the technique, and its limit

**Mutate to the fix that was REJECTED, not merely to break the correct one.** Breaking the right fix proves the
test notices *that* code; re-introducing the *wrong* design proves the test defends the DECISION. **Four instances,
all 2026-09-01, all of which went red exactly where they had to:**

| The rejected fix, re-introduced | What went red |
|---|---|
| Set `is_active = false` on the units of an archived property | "no flag is rewritten" **and** "a pre-paused unit stays paused" — the two tests that defend filtering over flag-mutation |
| Filter `OwnerPortalService::units()` — merge the two accessors into one | **the €300 test** — the owner's earned revenue and completed stay |
| Add a "save and apply" shortcut beside the season form | the separate-controls test — the two-step that is the feature's only protection |
| Make `covering()` use a different precedence rule from the write path | the divergence test — the defect the whole pass existed to remove |

⚠️ **ITS LIMIT, AND WHY SOME THINGS ARE RULES RATHER THAN TESTS: no mutation can catch a change that makes the
suite GREENER.** Pinning the one unpinned date case would have deleted the detector while turning everything green.
That is why "never pin the unpinned case" is written down instead of tested.
