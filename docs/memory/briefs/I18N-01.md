## 5. Phase A: make every text a key, with English staying byte-for-byte the same
Rules for converting strings. Every one of them caused a real bug in hrmzy:
- **One key per whole sentence or phrase.** Never glue two keys together with a space or a line break (for example "Add" + "unit"), because word order differs between languages. Dynamic parts become placeholders (`__('Paid :amount of :total')`), and plurals use trans_choice (nights, guests, units, rooms).
- **One key per meaning.** "Book" the verb is a different key from "Book" the noun, and "Open" the state is different from "Open" the action. The same goes for Balance, Rate, Stay and Block. Put the context in the key name or the export context.
- **One definition per concept, as Vyrobel already does.** Status words, stages, rails, category tags and owner/guest labels already live in shared helpers and enums (`RailLabel`, `ReservationStage` and the rest). Translate them there, with one key per value, never per view.
- **Never key a PHP array by a translated label.** If two labels translate identically, they collapse and an option or column disappears.
- **Escape translations used inside JS or HTML attributes** with @js() or e(). A straight quote in a French or Turkish translation must never break a script. Prefer typographic quotes inside translations.
- **Translate at render time** any text that is set before the locale is known: constructors, static properties, boot code, config, queued jobs.
- **Turn off CSS `text-transform` (uppercase/capitalize) for non-English.** That includes the uppercase category tags. It is wrong for Turkish i/İ and German ß, and it turns Georgian into Mtavruli, which the fonts lack.

The scanner that finds hardcoded English must follow Vyrobel's instrument rules. It tokenises PHP and Blade and skips comments, because a source-scanning guard reads its own needle. It must also be mutation-proven: plant a hardcoded string, a glued pair and a missing key, and each must turn it red. Remove them, and it must turn green again.

Proof that English is unchanged:
- The existing suite stays green **without editing a single assertion**. If an assertion needs to change during what should be a pure refactor, stop and tell me why.
- Also render every GET page for every realm and role before and after the conversion (as probe users), and diff the visible text.

- **Steps for each language**, in this order:
  1. Write the style guide.
  2. Translate a pilot batch and record the decisions in TODO-<lang>.md as FINAL/CORRECTION lines (the later line wins).
  3. Run one translator agent per batch.
  4. Run one independent reviewer agent per batch. It must not be the agent that translated that batch.
  5. Run one consistency editor: it catches the same short English string translated different ways, and drift from the glossary.
  6. Run the check script. It confirms that placeholders and HTML are identical to English, that no English is left except allowlisted text, that non-Latin languages use the right script, that no straight quote can break JS, that no label array collapses, and it gives length warnings.

  - Agents save their work in small chunk files, so a usage-limit stop loses nothing.
  - When relaunching an agent after a stop, tell it: "partial parts exist: verify, translate only what's missing, merge".
  - A fresh session must be able to continue from the words "continue the Vyrobel translation from ~/vyrobel-local/i18n/STATE.md".

## 10. Phase E: the permanent "what needs translation" system (the part I'll use every week)
1. **`php artisan lang:check`, the gate.** It checks every finished locale for:
   - MISSING keys;
   - PLACEHOLDER and HTML differences from English;
   - ENGLISH: text left untranslated;
   - JSQUOTE: quotes that can break JS;
   - COLLAPSE: labels in one array that translate identically;
   - GLUED: two keys joined together in a view.

   It exits with a non-zero code when there are errors. A Pest test runs it, so the suite and GitHub's checks enforce it.
2. **`php artisan lang:todo`, the report I'll ask for.** It lists the following, grouped by realm → role → screen, with file:line:
   - **NEW**: English keys with no translation yet, and the languages each is missing in;
   - **CHANGED**: keys whose English text changed after they were translated, which makes those translations stale. To detect this, store a hash of each key's English text at apply time, and compare against it on every run;
   - **HARDCODED**: visible English text that is not a key. This is the Phase A scanner, with an allowlist and a baseline so cases I've already accepted don't keep coming back;
   - **REMOVED**: keys no longer used, so they can be cleaned up.

   It prints a short summary (for example "Guest portal › Online check-in: 4 new texts, 1 changed, 27 languages each") and writes a full Markdown report plus a JSON report. Options: `--since=<git ref>` (and `--since=live`, which reads `.release`), `--locale=`, `--realm=`.
3. **Prove the instruments, the Vyrobel way.** Both commands get a `--self-test` that plants each kind of needle and must go red, and they are listed in RULES.md Part 3 next to the other instruments.
4. **Wire it in.** `ops/release.sh` preflight prints the lang:todo summary for what is being released and refuses to release if lang:check fails. Decide sensibly what warns and what blocks, and tell me what you chose.
5. **The delta procedure.** Write `~/vyrobel-local/i18n/DELTA.md`. It takes lang:todo's JSON and runs translate → review → consistency → check → apply → gate → render the touched screens, for all 27 languages. It reuses the glossary and the TODO decisions, so new texts use the same words as the old ones. When I say "translate the new texts", run this.
6. **Write the rule into CLAUDE.md and RULES.md**: every new or changed UI text is a key, following the Phase A rules. Every pass report ends with a lang:todo line saying what now needs translation.
