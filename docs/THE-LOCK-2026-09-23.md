# THE LOCK — vyrobel.com goes private without going quiet · 2026-09-23

> **A dated record.** True as of its date; never edited afterwards, only pointed at. The live surfaces are
> `ops/reference/public_html.htaccess`, `ops/htaccess-drift-check.sh` and `ops/exposure-battery.sh`.

## What changed, in one sentence

`vyrobel.com` now sits behind a **web-server password** with five machine-only routes exempted — a lock on
the door rather than a closed sign — and the site is **still parked** because one of the four proofs is the
founder's to complete.

## Why not maintenance mode

🔬 `queue:work` pauses while the app is down. Under maintenance every booking queues a job that never runs,
so nothing anyone tests behaves like production. The lock refuses at the web server, **before PHP**, which
leaves the application running normally for anyone who holds the password.

## Why Basic Auth and not an IP allowlist

A CDN terminates the connection (`server: hcdn`, measured DEPLOY 09), so the web server may see the edge's
address rather than the visitor's. Whether this host restores the real client IP **could not be measured**
without serving a probe file on a live public path — the wrong trade for a diagnostic. ⚠️ **A lock whose
correctness rests on an unmeasured variable is the wrong lock.** Basic Auth also survives his network
changing, which an IP rule does not.

🔬 Incidental discovery: the host is **LiteSpeed**, not Apache, reading `.htaccess` in compatibility mode.

## What is outside the lock, and why each one

| route | why it is exempt |
|---|---|
| `POST /webhooks/stripe`, `/webhooks/stripe/connect` | ⚠️⚠️ **A machine cannot type a password.** Stripe is wired but not yet calling, so a blocked webhook would be **silent for weeks** and surface as a reconciliation mystery — the quietest possible failure. |
| `POST /webhooks/channex/{channel}` | the channel manager is a machine too, and the same silence applies |
| `GET /up`, `GET /up/liveness` | the external dead-man's-switch polls these; an alarm that fails for the wrong reason teaches people to ignore it |

🔬 **No Postmark inbound or bounce route exists** — measured against `route:list`, not assumed. Nothing to
exempt today; if one is added it belongs on this list in the same change.

**Static assets are deliberately INSIDE the lock.** One origin means the browser replays credentials for
CSS/JS automatically, so the app renders normally; the cost is that the CDN caches nothing while the preview
is private. That is the right trade for a site with one intended visitor.

## Every exemption is `$`-anchored, and that is the load-bearing detail

`^/webhooks/` as a *prefix* would exempt `/webhooks/anything`. **On a money path an over-permissive check IS
the bug.** Each pattern names one real route and ends in `$`. 🔬 Proven against 24 cases locally and then
from outside — including `/upgrade` and `/uptime`, which a bare `^/up` would have let straight past.

⚠️ `Request_URI` excludes the query string, so `?cb=…` cache-busting cannot widen an exemption.

⚠️ Both `VY_PUBLIC` and `REDIRECT_VY_PUBLIC` are accepted: an internal redirect re-runs authorization on the
new URI and renames every env var with a `REDIRECT_` prefix.

## What was proven from outside, while still parked

The discriminator is the status code, not the challenge header (🔬 `WWW-Authenticate` rides along even on a
200). **401 = the lock refused, before PHP. 503 = the request reached PHP and maintenance refused.**

- 7 locked paths → **401** (`/`, `/login`, `/app/dashboard`, `/signup`, `/book/…`, a static asset, `/owner/…`)
- 5 exempt paths → **200 / 503**, never 401 — the request reached the application
- 5 traversal shapes out of an exempt path → **401**
- encoded slash, double slash, dot-segment, and two case variants → all correct
- 4 trailing-slash `301`s → each **terminates in 401** (the 301 is pre-auth path normalization by LiteSpeed
  and serves no content)

## ⚠️⚠️ What the lock broke, and how it was fixed

**`ops/exposure-battery.sh` silently started lying.** It classed `401` as "refused" — so applying the lock
moved 7 probes from `503` (honestly "unmeasurable") to `401` (falsely "refused") and the score went
**46 → 53 out of 53**. ⚠️ **The figure went UP the moment the site got safer. That is the tell.** A 401 is
the lock answering and is no evidence at all about the wall. 401 is now its own verdict and the honest
figure is **46 of 53 proven**; re-run with credentials to measure the wall underneath.

This is the same mistake as the 503 verdict, in a new costume, eleven hours later.

**`ops/htaccess-drift-check.sh` would have gone green over a file it no longer understood.** It now carries
17 rules + 3 anti-rules, and its self-test has a second half: deleting a rule proves the *presence* checks
fire and says nothing about a detector whose failure mode is something being **added**, so the unanchored
exemption is mutation-proven too.

## What is NOT proven, and who can prove it

⚠️ **"Correct credentials → the real app" is unproven, and deliberately so.** `.htpasswd` exists and is
**0 bytes**, so the lock currently refuses *everyone* — strictly more locked than it will be, with no key
that any session chose. The founder sets the password with:

```
/opt/alt/php84/usr/bin/php ~/domains/vyrobel.com/vyrobel-lock.php
```

🔬 `htpasswd` is **not installed** on this host, which is why that file exists. It prompts twice without
echoing, keeps the password off every command line (visible in `ps` on shared hosting), writes the hash
mode-600 outside the web root, then **makes two real requests to `vyrobel.com` and reports what came back** —
falling back from bcrypt to `{SHA}` if this server will not read the first. A lock that is assumed to work
is not a lock.

## Why the site is still parked

The brief's order is: prove refusal from outside → lift maintenance → four proofs. Proof two needs a
password only the founder can set, so the pass stops one step short with **both** layers still on. The
failure directions are asymmetric: a lock that wrongly refuses him fails safe and he tells us; maintenance
lifted over a lock that does not hold makes the site public, and you cannot un-see a site.

**Parked is free.**
